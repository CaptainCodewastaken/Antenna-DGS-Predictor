# Physics Under Glass — Antenna DGS Predictor

## Problem Statement
How might we build a visually stunning antenna design tool where the interactive canvas *is* the interface, and rigorous physics depth is revealed progressively — so that non-expert judges are wowed at first sight, and expert evaluators find defensible physics one click deeper?

## Recommended Direction

**"Physics Under Glass"** — a single cohesive experience with three progressive layers of depth, all built into one visual canvas:

### Layer 1: The Design Canvas (what judges see first)
A real-time rendered antenna schematic (rectangular patch on substrate with ground plane) that updates live as the user adjusts dimensions via sliders. The user places **rectangular slot DGS** (1 or 2 slots, variable position/size) on the ground plane by clicking. Every parameter change triggers an instant re-prediction, and the **2D polar radiation pattern** and **3D radiation surface** animate to reflect the new configuration. Prediction results (frequency, gain) appear as elegant, animated dashboard cards.

### Layer 2: The Physics Reveal (one click deeper)
Click on any predicted value → an expandable panel shows:
- The **cavity model equation** that produced the resonant frequency (with actual computed terms)
- The **equivalent-circuit model** for the selected DGS pattern (L, C component values, resonant frequency shift)
- **S-parameter / Return Loss (S₁₁) plot** across a frequency sweep
- Hover over the radiation pattern → angular coordinates and dB values follow the cursor

### Layer 3: The ML Arena (the analysis drawer)
A collapsible "Model Comparison" section showing:
- **Live leaderboard**: all models (Linear Regression, Ridge, Lasso, KNN, Decision Tree, Random Forest, XGBoost, SVR) ranked by accuracy for the current prediction
- **Per-model metrics**: R², MAE, RMSE with confidence intervals
- **Cross-validation scores** and **learning curves**
- **Feature importance** visualization (which antenna dimensions matter most)
- The physics engine prediction labeled as "Analytical (Ground Truth)" for comparison

## Key Assumptions to Validate
- [ ] **Rectangular slot DGS equivalent-circuit model is well-validated** — the parallel LC resonator model for rectangular slots is widely published. Verify closed-form L/C expressions against 2-3 IEEE/Springer papers.
- [ ] **Dumbbell DGS (stretch goal) has usable published models** — search for equivalent-circuit papers. Only add if found with validated parameter mappings.
- [ ] **Cavity model radiation pattern looks physically plausible** — validate by comparing our cos²θ far-field pattern against a known HFSS screenshot for a similar patch. The shape should match even if magnitudes differ slightly.
- [ ] **Synthesized data is physically valid** — all generated samples must satisfy physical constraints (patch < substrate, frequency in realistic range, gain bounded by aperture theory). Invalid samples must be rejected during generation.
- [ ] **Real-time canvas updates are smooth** — the physics engine is closed-form (μs), ML inference is single-sample (~ms). Bottleneck is rendering. Validate with a Plotly prototype early.
- [ ] **Rectangular slot DGS provides sufficient variety** — variable slot count (1-2), position, and dimensions should provide enough parameter space for a compelling demo and robust ML training.

## MVP Scope

### In Scope
| Component | Details |
|-----------|---------|
| **Antenna type** | Rectangular microstrip patch only |
| **Substrate** | User-configurable dimensions + permittivity (FR4 default, Rogers presets) |
| **DGS patterns** | **Primary:** Rectangular slots (1-2 slots, variable width/length/position). **Stretch:** Dumbbell (only if published equivalent-circuit model is validated). |
| **Physics engine** | Cavity model (resonant freq) + aperture theory (gain) + equivalent-circuit DGS perturbation + far-field radiation pattern computation (E-plane, H-plane) |
| **Outputs** | Resonant frequency (GHz), Gain (dBi), S₁₁ return loss, 2D polar radiation pattern, 3D radiation surface |
| **ML models** | Linear Regression, Ridge, Lasso, KNN, Decision Tree, Random Forest, XGBoost, SVR — all trained on physics-engine-generated data |
| **Model comparison** | Side-by-side predictions, accuracy metrics, feature importance, learning curves |
| **Dataset** | Generated by the physics engine (5,000–10,000 samples with varied geometries + DGS configurations). Every sample must be physically valid — enforced constraints on geometry, frequency, and gain ranges. |
| **Frontend** | Vite + React, interactive canvas (SVG/Canvas), Plotly for plots, Three.js or Plotly 3D for radiation surface |
| **Backend** | Python FastAPI serving physics engine + trained ML models |
| **UI aesthetic** | Dark mode, glassmorphism, micro-animations, premium typography (Inter/JetBrains Mono) |

## Not Doing (and Why)
- **Circular patches** — adds Bessel function complexity for marginal demo value. Rectangular is sufficient.
- **Arbitrary polygon DGS** — no published equivalent-circuit model exists; accuracy would be fabricated.
- **H-shape DGS** — insufficient published equivalent-circuit models for rigorous implementation.
- **Deep learning models** — prone to overfitting on small analytical datasets; XGBoost is the right ceiling.
- **Inverse design mode** — compelling but doubles scope. Forward prediction + DGS placement is the core story.
- **3D CAD-quality antenna rendering** — SVG/Canvas schematic is sufficient. This isn't SolidWorks.
- **Real EM simulation integration** — no simulator access; analytical engine is the explicit constraint.
- **Mobile responsive design** — this is a desktop demo tool for a project evaluation.

## Open Questions

- Should the data generator sweep DGS parameters independently or use a Latin Hypercube sampling strategy for better coverage?
- What frequency range should the S₁₁ plot span? (Probably 1–10 GHz to cover typical patch antenna operation.)
